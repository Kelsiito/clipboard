# Security and privacy

## Scope

`clipboard` is a local macOS application that stores clipboard history on the user's Mac. It has no server, account system, analytics, telemetry, or cloud synchronization.

Clipboard entries may contain passwords, tokens, personal data, or confidential work. Treat the local history file as sensitive data.

## Reporting a vulnerability

Please do not publish exploitable details in a public issue.

If private vulnerability reporting is available for this repository, use GitHub's **Security → Report a vulnerability** flow. Otherwise, contact the maintainer through the GitHub profile and share only the minimum information required to reproduce the issue. Include the affected commit, macOS version, reproduction steps, and impact; never include real clipboard contents, credentials, or personal files.

If a report is received publicly, maintainers may redact or remove sensitive details and move the discussion to a private channel.

## Data handling

- History and Library files are stored locally under `~/Library/Application Support/clipboard/` in authenticated AES-GCM envelopes.
- The 256-bit storage key is generated locally and stored in Keychain with `WhenUnlockedThisDeviceOnly` accessibility; it is not synchronized or uploaded.
- Existing plaintext data is migrated only after successful decoding. A key/decryption failure preserves the existing file and blocks further writes to that store for the session.
- Optional Touch ID or Mac-password authentication can protect opening History and the Library. It does not send biometric data to the app, stop background capture, or claim to encrypt process memory.
- The app ignores concealed, transient, and autogenerated pasteboard entries.
- File history stores bookmarks/references, not copies of the original files.
- Clearing history removes app-owned history only; it does not delete source files.
- Automatic paste uses macOS Accessibility. The permission is optional, and the app provides a manual-paste fallback when it is not granted.
- The current source build is unsigned and not notarized. Only run builds from sources you trust.

## Maintainer checklist

Before merging a security-sensitive change:

1. Confirm that no clipboard contents, credentials, or local paths are added to logs, tests, screenshots, or documentation.
2. Review persistence and file-bookmark changes for data exposure and destructive behavior.
3. For encrypted-storage changes, test legacy migration, authenticated-purpose separation, tamper rejection, and fail-safe preservation with deterministic synthetic keys.
4. Run the unit tests, build, and `git diff --check`.
5. Document any permission change and its user-visible fallback.
