# Project Summary

## Status

`clipboard` is a public, source-first macOS clipboard history app. The v1 implementation is complete, builds with Xcode, and is published under the MIT license. The app is currently unsigned and not notarized.

## User-facing behavior

- The app runs as a menu-bar accessory and does not appear as a normal Dock app.
- `⌘⇧V` opens a compact history picker; the hotkey can be changed in Settings.
- The picker shows three rows, supports scrolling, arrow navigation, `Enter`, `Esc`, click-outside dismissal, and a close button.
- Items can be pinned, with a maximum of three pinned entries shown first.
- Settings cover the hotkey, a 10–200 history limit, clearing app-owned history, and Accessibility status.
- The current app UI copy is PT-PT. Repository documentation, developer-facing guidance, and source identifiers are English.

## Storage and privacy

- History is stored locally in `~/Library/Application Support/clipboard/history.json`.
- Text, RTF data, and image payloads are persisted locally.
- Copied files are represented by local bookmarks/references; original files are never copied or deleted by the app.
- Concealed, transient, and autogenerated pasteboard entries are ignored.
- There is no cloud sync, account, backend, analytics, telemetry, or network service.
- Clearing history removes only app-owned history.

## Architecture

- `clipboardApp.swift`: menu-bar scene and app lifecycle.
- `AppState.swift`: settings, global hotkey orchestration, target-app capture, Accessibility status, and paste flow.
- `PasteboardMonitor.swift`: general pasteboard polling and filtering.
- `ClipboardStore.swift`: local persistence, deduplication, history limits, and pin ordering.
- `Models.swift`: Codable clipboard, file-reference, and hotkey models.
- `GlobalHotKey.swift`: Carbon global hotkey registration.
- `ClipboardPanelController.swift`: floating picker, placement, animations, keyboard navigation, and rows.
- `SettingsView.swift`: settings UI and Liquid Glass/material compatibility helpers.

## Positioning behavior

When Accessibility is available, the app resolves the target app before activating its own UI and uses the focused standard text role's caret or selection bounds. Coordinates are converted per display before the panel is placed.

If the target app does not expose an editable text element, the app never uses the mouse location. It chooses the largest normal target window and uses a deterministic area fallback. The Codex desktop app exposes its content as a full-window `AXGroup` and has a separate title-bar window; the fallback therefore selects the main window and anchors near its lower composer area.

Without Accessibility, the item is still restored to the system pasteboard. Automatic `⌘V` is skipped and the user can paste manually.

## Validation

The current local validation set is:

```sh
xcodebuild -project clipboard.xcodeproj -scheme clipboard -destination 'platform=macOS' test
xcodebuild -project clipboard.xcodeproj -scheme clipboard -destination 'platform=macOS' build
git diff --check
```

The XCTest suite covers persistence, images, file bookmarks, deduplication, limits, pinning, empty and legacy data, hotkey defaults, and panel placement geometry. The GitHub Actions workflow runs the test and build commands on macOS for pushes to `main` and pull requests.

## Manual QA checklist

- Text, image, and multiple-file capture and paste.
- Restart persistence.
- Default and changed hotkeys.
- Three-row scrolling and pin limit.
- Close button, `Esc`, outside click, and click-to-paste dismissal.
- Menu-bar Settings and Quit actions.
- Settings above other apps.
- Accessibility granted and denied.
- Standard text-editor caret positioning.
- Window-area fallback for apps that do not expose a caret.

Manual fixtures must be synthetic and must not contain real clipboard history or credentials.
